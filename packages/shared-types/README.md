# @slate/shared-types

Контракты между `apps/api` и `apps/web`: границы значений, zod-схемы входов и ответов,
выведенные из них типы. Один источник правды — схема; типы получаются через `z.infer`, а не
пишутся рядом.

```ts
import { upsertElementSchema, type UpsertElementInput } from '@slate/shared-types';
```

## Кто как этим пользуется

| Сторона    | Роль пакета                                                           |
| ---------- | --------------------------------------------------------------------- |
| `apps/web` | рантайм-валидация (react-hook-form + zod) и типы форм                 |
| `apps/api` | **типы** входных DTO (`implements`) и общие константы для декораторов |

Бэкенд остаётся на class-validator: декораторы работают с Nest-овым `ValidationPipe`, а схемы
дают им ТИП. Расхождение полей DTO и контракта роняет сборку бэка (`implements` + `ExactKeys`),
а не всплывает 400-ым у пользователя.

Выходы (`*ResponseSchema`) через `implements` не привязаны — на проводе даты это строки, а в
DTO бэкенда `Date`. Их сверка — парсинг настоящих тел ответов в e2e (`apps/api/test`).

## Сборка

Пакет собирается **дважды**: ESM для Vite и CommonJS для Nest.

```
pnpm --filter @slate/shared-types build
```

Типы при этом резолвятся прямо из `src` (условие `types` в `exports`), поэтому `typecheck` и
редактор работают без предварительной сборки, а `dist` нужен только рантайму приложений.
